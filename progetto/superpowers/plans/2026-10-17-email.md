# W15 Email dell'app: piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** inviti con l'email verificata tramite il link «Scegli la password», «Password
dimenticata», etichetta «Deve ancora scegliere la password», lingua delle email allineata ed
email operative dal Worker con l'API di Resend.

**Architecture:** le email per le persone le spedisce Supabase Auth (SMTP su Resend, già
configurato) con i template `invite` e `recovery`, che portano a `/password#token_hash=…`;
il Worker crea l'account senza password e chiede l'invio con `POST /auth/v1/invite`. Le email
operative le spedisce il Worker con una `fetch` all'API di Resend, una sola volta per evento
grazie alla tabella `app.ops_alerts`.

**Tech Stack:** TypeScript, oRPC, zod 4, Postgres.js, Supabase Auth (API di amministrazione,
`supabase-js` nel browser), Cloudflare Workers (Cron Trigger), React con TanStack Router,
Vitest, pgTAP, Mailpit dello stack locale.

**Spec:** `progetto/superpowers/specs/2026-10-17-email.md` (leggerla tutta prima di ogni
task; i numeri di sezione qui sotto rimandano a lei).

## Global Constraints

- Nessuna dipendenza nuova (niente SDK di Resend).
- Codice, identificatori, commenti e test in inglese; testi per gli utenti in italiano e
  inglese britannico; italiano senza genere; commit piccoli in italiano.
- Nei log mai password, token, email, indirizzi né corpi di richiesta e risposta: solo id,
  codici, numeri, stati HTTP (`logEvent` di `server/src/log.ts`).
- `SUPABASE_SECRET_KEY` la legge solo `server/src/accounts/`, sempre nell'intestazione
  `apikey`, mai come `Bearer`.
- Migrazione solo additiva: `supabase/migrations/20261017100000_email.sql`; ricontrollare su
  `origin/main` che non esista una versione uguale o successiva prima della PR.
- Prove solo sullo stack locale: mai credenziali di produzione, mai email verso indirizzi
  veri, mai una chiave Resend vera; per la SPA il server di sviluppo con `VITE_SUPABASE_URL`
  locale, controllando l'URL di Auth nelle richieste prima di accedere.
- Durata del codice delle email 24 ore (`otp_expiry = 86400`); attesa di «Rimanda l'email» e
  «Manda di nuovo» 60 secondi; password di almeno 8 caratteri e al più 72 byte, regole e testi
  del cambio dal Profilo.
- Mittente `Cosa si mangia <noreply@cosasimangia.app>`; allarmi a `OPS_ALERT_EMAIL`; riprova
  fino a 5 tentativi entro 48 ore; pulizia oltre 90 giorni.
- Prenotazione e chiusura degli inviti (funzioni SQL di A e C) non cambiano.
- Comandi: `npm test -w server`, `npm test -w web`, `npm test -w contract`, `supabase test db`,
  `npm run typecheck`; i test sullo stack girano con le variabili `STACK_*` (vedi
  `server/test/stack/invitations.stack.test.ts`).

## Review Focus

1. **Email scritta con maiuscole o spazi** («Anna@Example.com »): il server la normalizza già
   nella prenotazione; `sendPasswordEmail` e `resetPasswordForEmail` devono usare l'email
   normalizzata restituita da `accept` (`email` della risposta), non quella del campo. Test
   nel Task 4 e nel Task 12.
2. **Ricaricamento di `/password` dopo la verifica** (frammento già tolto): la pagina non deve
   mostrare un modulo che poi fallisce con «password attuale richiesta» senza spiegazione.
   Test nel Task 11.
3. **Due esecuzioni del cron che segnalano lo stesso evento insieme**: una sola email.
   Test nel Task 7 (due `raiseAlert` concorrenti con la stessa chiave → una chiamata a
   Resend).
4. **Nome della famiglia con caratteri HTML** (`<b>Rossi & figli</b>`): nel template è
   escapato da `html/template`; nei metadati si salva il testo com'è. Test sullo stack nel
   Task 14.
5. **Allarme dell'esportazione quando alle 02:30 è andato tutto bene**: alle 04:30 la funzione
   salta (`skipped`) e non deve segnalare nulla. Test nel Task 8.
