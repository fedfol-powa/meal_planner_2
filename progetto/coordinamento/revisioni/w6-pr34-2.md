**Rilievi**

1. **Bloccante — Il rilascio scarta l’elenco delle migrazioni pendenti.**

   Riferimenti: [scripts/release.ts:302](/Users/fedfol/Projects/meal_planner_2/.worktrees/review-pr34-2/scripts/release.ts:302), righe 211 e 266.

   Quando un comando riesce, `realDeps.run` conserva solo stdout. Supabase CLI scrive invece l’elenco del dry run su **stderr**, come confermato nel [codice della versione 2.120.0](https://github.com/supabase/cli/blob/v2.120.0/apps/cli/src/command-internal/db-push-core.ts).

   Ho eseguito il comando reale con credenziali sintetiche e processi simulati: pur ricevendo una migrazione pendente su stderr, termina con codice 0 e «No pending migrations: nothing to apply». L’applicazione salterebbe quindi `db push`; nel rilascio completo potrebbe pubblicare codice senza lo schema necessario.

   **Correzione:** conservare separatamente stdout e stderr; analizzare entrambi per Supabase, mantenendo stdout separato per le risposte JSON di Wrangler. Aggiungere una regressione attraverso il wrapper reale. Il test `fresh-database.test.ts` non scopre il difetto perché il suo wrapper unisce già i due flussi.

2. **Importante — `sslrootcert` non quotato altera la connessione di psql.**

   Riferimento: [scripts/import/load/target.ts:92](/Users/fedfol/Projects/meal_planner_2/.worktrees/review-pr34-2/scripts/import/load/target.ts:92).

   Confermato il punto segnalato. Un percorso con spazi viene inserito direttamente nella conninfo. Ho verificato che il parametro sintetico:

   ```text
   sslrootcert=/Users/fedfol/.config/cosasimangia/ca+sslmode=disable+host=other.invalid
   ```

   supera la validazione con una CA simulata e produce:

   ```text
   … sslmode=verify-full sslrootcert=/Users/fedfol/.config/cosasimangia/ca sslmode=disable host=other.invalid
   ```

   I `+` diventano spazi: psql interpreta nuovi parametri, mentre anteprima e impronta conservano l’endpoint originario. Nell’esecuzione reale deve esistere il file con quel nome. Un normale percorso con spazi può invece semplicemente impedire la connessione.

   **Correzione:** quotare i valori conninfo ed effettuare l’escaping di apici e backslash secondo [libpq](https://www.postgresql.org/docs/17/libpq-connect.html), oppure passare il percorso tramite `PGSSLROOTCERT` nell’ambiente del container. Provare spazi, apici, backslash e testo simile a parametri.

3. **Importante — Gli override di Wrangler possono ancora arrivare dai file `.env`.**

   Riferimenti: [scripts/release.ts:325](/Users/fedfol/Projects/meal_planner_2/.worktrees/review-pr34-2/scripts/release.ts:325), righe 201 e 275.

   Il controllo esamina soltanto l’ambiente del processo padre. Wrangler carica successivamente `.env` e `.env.local` dalla directory corrente, quindi `server/`; questi file possono essere ignorati da Git.

   Con Wrangler 4.149.0 ho verificato in una directory temporanea che `.env` contenente `CLOUDFLARE_ENV=review-other` seleziona l’ambiente anche senza una sezione `env`. Il nome effettivo diventa `cosasimangia-review-other`. Il controllo dell’output intercetterebbe la divergenza **dopo la pubblicazione**, quando la scrittura non confermata è già avvenuta.

   **Correzione:** impedire il caricamento implicito dei file d’ambiente, per esempio passando a ogni comando Wrangler un `--env-file` temporaneo vuoto, oppure validare preventivamente tutti i file effettivamente caricati. Aggiungere la regressione con override nel file e ambiente del padre pulito.

4. **Importante — L’eccezione `ON COMMIT` attraversa il confine fra istruzioni.**

   Riferimento: [scripts/prod-sql/tokens.ts:93](/Users/fedfol/Projects/meal_planner_2/.worktrees/review-pr34-2/scripts/prod-sql/tokens.ts:93).

   `previousWord` non viene azzerato al punto e virgola. Ho verificato che `checkSqlText` accetta:

   ```sql
   SET enable_seqscan = on;
   COMMIT;
   DELETE FROM app.families;
   ```

   Il `COMMIT` viene scambiato per l’opzione di una tabella temporanea. Se questo testo entrasse in uno script ammesso, l’anteprima eseguirebbe il `DELETE` fuori dalla transazione.

   La lista chiusa protegge gli script attuali: non ho trovato questa sequenza nei file ammessi, né un modo di introdurla tramite `--set`. Resta però incompleta la difesa esplicitamente richiesta.

   **Correzione:** riconoscere i confini delle istruzioni e limitare l’eccezione alla clausola `ON COMMIT` pertinente. Aggiungere il caso ai test unitari e alla prova con psql locale.
